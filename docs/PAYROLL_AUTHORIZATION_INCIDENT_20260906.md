## Changes

- Check the proof service's live gas balance before starting proof generation.
  `PAYO_PROOF_RELAYER_MIN_BALANCE_FRI` defaults to 100 STRK as an operational
  admission reserve for four verifier transactions. This is not a fee quote or
  a reservation across concurrent payrolls.
- Under the existing shared nonce lock, estimate each submission once, check
  balance against all three maximum resource bounds, and submit those exact
  bounds. Preserve a funding-blocked book job without exhausting its retry
  counter; the existing proof expiry guard still applies.
- Keep polling a durable authorization through transient HTTP failures. Stop on
  revoked authorization, permanent job failures, and actionable funding errors.
- Retry an identical enqueue after a lost response. An already verified bundle
  can replay only its matching existing authorization.
- Fetch only public status fields during polling, without loading full proof
  calldata from PostgreSQL for every status request.
- Offer `Resume saved payroll` in payroll history. Check canonical seal recovery
  first, then reconstruct an unpaid book authorization from encrypted records.
  Validate the roots, chain, proof window, artifacts and callback before creating
  the idempotent Ready approval intent. No new proof is generated by this path.
