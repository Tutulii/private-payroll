# PAYO circuits

`payroll_integrity` is the v1 private calculation circuit. It binds a fixed 64-leaf agreement set to a fixed 64-leaf payroll manifest and proves, for up to 50 active lines:

- complete one-to-one agreement coverage and uniqueness;
- integer earnings, deductions, and net-pay arithmetic;
- STRK/USDC token allowlisting;
- due-date and final-pay completeness gates;
- classification-treatment consistency;
- an exact FX conversion and minimum reference-value floor.

The roots and run nullifier are the only payroll-specific public values. Policy-catalog membership and oracle-snapshot membership are the next circuit composition; the current circuit accepts already committed policy and schedule values and must not be marketed as statutory certification.

## Pinned verifier pipeline

The pipeline follows the audited Garaga UltraKeccakZKHonk path:

```bash
cd circuits/payroll_integrity
nargo test
nargo build
nargo execute witness

bb write_vk --scheme ultra_honk --oracle_hash keccak \
  -b target/payo_payroll_integrity.json -o target
bb prove --scheme ultra_honk --oracle_hash keccak \
  -b target/payo_payroll_integrity.json -w target/witness.gz \
  -k target/vk -o target

cd ../../contracts
garaga gen --system ultra_keccak_zk_honk \
  --vk ../circuits/payroll_integrity/target/vk \
  --project-name integrity_verifier
```

Compatibility set: Noir `1.0.0-beta.16`, Barretenberg `3.0.0-nightly.20251104`, Garaga `1.1.0`, Cairo `2.16.1`, Starknet Foundry `0.57.0`. Never mix proof, calldata, and verifier artifacts generated by different sets.

The same verifier-key pipeline runs in `.github/workflows/proof-artifacts.yml` on an isolated x64 runner. The 64-leaf circuit currently reports 530,064 ACIR opcodes; use the workflow or a development machine with sufficient prover memory rather than treating an interrupted mobile build as an artifact.
